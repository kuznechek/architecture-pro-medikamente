# Задание 3. Оценка Data Encryption at Rest and In Transit

## Классификация данных: необходимость защиты и инструменты

| Данные | В чём необходимость защиты | Инструменты защиты |
|--------|---------------------------|---------------------|
| **PII пациента** (ФИО, СНИЛС, полис, адрес, телефон) | ФЗ‑152, штрафы до 500 тыс. руб., уголовная ответственность при утечке | Шифрование в PostgreSQL (pgcrypto, AES-256), TLS 1.3 для передачи, аудит доступа через триггеры |
| **Медицинская тайна** (диагнозы, анализы, история болезни) | Уголовная ответственность, потеря лицензии | Шифрование столбцов в PostgreSQL, шифрование файлов в MinIO (SSE‑S3), контроль доступа через Keycloak |
| **Финансовые данные** (суммы оплат, услуги) | Составляющая ПДн, важна для достоверности отчётности, защита от мошенничества | TLS между сервисами, шифрование бэкапов, обезличивание перед аналитикой (Presidio) |
| **Аутентификационные данные** (пароли, JWT, API‑ключи) | Без них вся защита бессмысленна, риск полного захвата системы | Хеширование паролей (Keycloak), JWT с коротким сроком, хранение ключей в защищённой таблице или Vault |
| **Аудиторские логи** | Необходимы для расследования утечек и доказательства соблюдения ФЗ | Триггеры PostgreSQL, запись в отдельную таблицу, защита логов от изменения |
| **Согласия пациентов** | Основание для обработки ПДн, без них обработка незаконна | Хранение в PostgreSQL с шифрованием, электронная подпись, проверка при каждом доступе |


## Шифрование данных при хранении (at rest)

**Улучшение :**  
- Все персональные данные (ФИО, СНИЛС, адрес) и медицинская тайна шифруются в PostgreSQL с помощью AES‑256
- Сканы медкарт и файлы в MinIO шифруются автоматически (SSE‑S3)
- Бэкапы БД шифруются отдельным ключом

Выполнение требований ФЗ‑152 и ФЗ‑323 (врачебная тайна). Защита от утечки при краже дисков, бэкапов или несанкционированном доступе к файловому хранилищу.


## Шифрование данных при передаче (in transit)

**Улучшение :**  
- Все внешние и внутренние API работают только по TLS 1.3
- Kafka и Debezium используют TLS + SASL/SCRAM для защиты потоков данных
- Подключение к PostgreSQL требует TLS (`sslmode=require`)
 
Исключается перехват трафика («man‑in‑the‑middle»), подмена сообщений в Kafka, прослушивание соединений между сервисами. Это критично для медицинских данных и платежной информации.


## Автоматизированный контроль защиты

**Улучшение :**  
- В PostgreSQL устанавливаются триггеры, которые логируют каждое чтение/изменение полей с PII (аудит доступа)
- Prometheus + Blackbox exporter проверяют срок действия TLS‑сертификатов и наличие шифрования на всех серверах
- Автотесты в CI/CD проверяют, что в топики Kafka не попадают необезличенные ПДн. 

Автоматический контроль гарантирует, что защита не отключается «по ошибке». Логи аудита нужны для расследования инцидентов и доказательства соответствия регуляторам (РКН). Мониторинг сертификатов предотвращает внезапные отказы в работе.
