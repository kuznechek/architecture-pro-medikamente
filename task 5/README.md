# Задание 5. Разработка cutover-плана

## Cutover‑план миграции ИС «Медикаменте» (Parallel run)

| Стратегия | Суть | Применимость к «Медикаменте» |
|-----------|------|------------------------------|
| **Big Bang** | Остановка старой системы и мгновенный переход на новую | **Высокий риск** – критичны для бизнеса запись пациентов, оплаты, доступ к медкартам. При сбое – полная остановка работы. Не подходит из‑за необученного персонала и новых процессов (Kafka, ClickHouse) |
| **Parallel run** | Старая и новая системы работают одновременно, нагрузка переводится постепенно | **Оптимально** – позволяет сравнить результаты, обучить сотрудников в реальном режиме, сохранить откат. Двойной ввод данных на старте компенсируется контролем качества и автоматической синхронизацией. |
| **Phased** | Поэтапная замена модулей | Сложно из‑за тесной связности данных (Excel, 1С, общий диск) |

Parallel run выбран для минимизации рисков простоя бизнеса, обеспечения контроля корректности данных и плавного обучения персонала.

### Ключевые риски, роли и ответственность

| Риск | Вероятность | Влияние | Мера снижения |
|------|-------------|---------|----------------|
| Рассинхронизация данных между старой и новой системами | Средняя | Высокое | Автоматическая сверка каждые 15 минут, CDC (Debezium), ручная выверка в конце дня |
| Отказ Kafka / ClickHouse при нагрузке | Низкая | Критическое | Горизонтальное масштабирование, реплики, алертинг, запас ресурсов +50% |
| Ошибки персонала при двойном вводе | Высокая | Среднее | Упрощённые формы, автоматическая проверка дублей, поощрение за безошибочность |
| Сбой интеграции с 1С | Средняя | Высокое | Шлюз с буферизацией (RabbitMQ), повторные попытки, ручной интерфейс исправления |
| Потеря данных при откате | Низкая | Критическое | Регулярные бэкапы (каждые 15 минут), проверка процедуры отката на стенде |

### RACI-матрица ответственности

- **R** – исполнитель (responsible)  
- **A** – ответственный за результат (accountable)  
- **C** – консультирует (consulted)  
- **I** – информируется (informed)

### Критерии успешного завершения cutover

- 100% критических операций (запись, оплата, просмотр медкарты) выполняются через новую систему без сбоев
- Время отклика системы <500 мс при пиковой нагрузке
- Все пользователи прошли обучение и работают без постоянной поддержки
