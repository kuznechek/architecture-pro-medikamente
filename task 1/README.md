# Задание 1. Анализ безопасности системы

## Задача 1. Конфиденциальные данные, которые не учтены во внутренних системах

### Сейчас в явном виде в системах учтены:

- Данные о деньгах (1С:Бухгалтерия)

- Товарно-материальные ценности (1С:Торговля и склад)

### Неучтённые данные :

| Категория                | Примеры данных                                      | Чувствительность | Где хранятся сейчас                     | Риск отсутствия в системах                          |
|--------------------------|-----------------------------------------------------|------------------|------------------------------------------|------------------------------------------------------|
| Пациенты (PII)           | ФИО, адрес, телефон, СНИЛС, полис ОМС/ДМС           | Высокая          | Excel, общий диск                        | Утечка PII, штрафы до 500 тыс. руб. по ФЗ-152       |
| Медицинская тайна        | Диагнозы, результаты анализов, история болезни      | Очень высокая    | Сканы медкарт, Excel, общий диск         | Нарушение врачебной тайны (ст. 13 ФЗ-323), уголовная ответственность |
| Финансы пациентов        | Суммы оплат, даты платежей, привязка к услугам      | Средняя          | Excel "Учёт платежей", общий диск        | Несоответствие с 1С, ошибки в отчётности            |
| Сотрудники (PII)         | Паспортные данные, ИНН, СНИЛС, зарплата (если есть) | Высокая          | Возможно, Excel или сканы на общем диске | Нарушение ФЗ-152, риск внутренних утечек            |
| Доступы и аудит          | Кто, когда и какие данные смотрел/изменял           | Высокая          | Не логируется совсем                     | Невозможно доказать нарушение, анонимный доступ     |


### **Особенно критично:**

- Медицинские карты в сканах — доступны всем, у кого есть доступ к общему диску

- Нет разграничения прав доступа

- Нет аудита доступа (нарушение Privacy By Design)

### Системы:

- Общий диск (файловая шара) — Excel + сканы

- 1С:Бухгалтерия

- 1С:Торговля и склад

- ККМ

### Проблемы безопасности:

- Конфиденциальные данные в открытом доступе

- Нет разграничения ролей

- Нет шифрования

- Нет Data Lineage (откуда данные, кто менял)

- Избыточные данные (нарушение Data Minimization)

## Задача 2. Аудит мер по обеспечению безопасности данных

[### Список проблемных зон](https://github.com/kuznechek/architecture-pro-medikamente/blob/feature/task%201/problems.md)

### Соответствие архитектурным практикам

| Практика | Реализация в As-Is | Проблема |
|----------|-------------------|-----------|
| **Privacy by Design** | Не реализована — данные не защищены по умолчанию, доступ открыт. | Точечные меры защиты отсутствуют. |
| **Data Minimization** | Нарушена — хранятся все данные, нет политики удаления. | Избыточные данные — риск. |
| **Data Lineage** | Отсутствует — нет логирования доступа и изменений. | Невозможность аудита. |

## Задача 3. Что можно улучшить?

1. Внедрить единую медицинскую ИС с ролевой моделью, шифрованием и аудитом.
2. Убрать общий диск — перейти в защищённое облако или локальную БД с контролем доступа.
3. Оцифровать согласия пациентов и связать с записями.
4. Определить ответственного за ПД и разработать политику удаления данных.
5. Зашифровать каналы между ККМ и 1С, а также диски с данными.

### Данные для защиты и способы

| Данные | Способ защиты |
|--------|----------------|
| PII пациента (ФИО, СНИЛС, телефон, адрес, полис) | Шифрование (AES-256) + обезличивание для аналитики |
| Медицинская тайна (диагнозы, анализы, история) | Шифрование + обфускация на экране |
| Финансовые данные пациента (суммы, услуги) | Шифрование при передаче (TLS) + обезличивание |
| PII сотрудника (паспорт, ИНН, зарплата) | Шифрование + обфускация |
| Логи доступа (аудит) | Хеширование (SHA-256) + шифрование |
| Согласия пациентов | Электронная подпись + шифрование |

### Механизм тегирования данных

**Инструменты:** Varonis, Microsoft Purview, Apache Atlas, самописные скрипты (regex).

**Процесс:**
1. Автосканирование файлов и БД.
2. Обнаружение конфиденциальных данных (по шаблонам: СНИЛС, полис, медицинские термины).
3. Присвоение тегов: `PII_High`, `Medical_Secret`, `Financial`, `Public`.
4. Применение политик: шифрование, ограничение доступа, аудит.
5. Автоудаление по сроку хранения.

### Инструменты и меры для защиты потоков

| Поток данных | Меры защиты |
|--------------|--------------|
| Пациент → Администратор | Запрет записи на личные устройства, обучение |
| Администратор → Excel (общий диск) | Замена Excel на медицинскую ИС, шифрование диска (BitLocker), ролевой доступ |
| ККМ → 1С:Бухгалтерия | TLS 1.3, VPN, шифрованный OLE |
| Общий диск → пользователи | Замена на S3+SSE, IAM политики, 2FA |
| Сканирование медкарт | Шифрование на лету, тегирование, удаление локальных копий |
| Бухгалтерская сверка | API вместо ручной, обезличенные данные |
| Доступ врачей | RBAC, MFA, обфускация диагнозов |
| Аудит | SIEM (Wazuh, ArcSight), DLP, мониторинг аномалий |
